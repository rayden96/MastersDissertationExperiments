# Experiment Design Conventions

This document defines how every experiment in this repository is structured, logged, saved, checkpointed, and plotted. It exists so that:

- runs that die mid-execution (especially in Colab) don't lose work,
- plots can be regenerated from saved data at any time without retraining,
- results across chapters stay comparable,
- future-me (or a collaborator) can rerun any experiment from scratch by opening one notebook.

If you are adding a new experiment, follow this document literally. If you find yourself wanting to deviate, update the document first and justify the change.

---

## 1. Folder layout

```
experiments/<chapter>/<NN_name>/
    run.ipynb        # produces data, nothing else
    plots.ipynb      # reads saved data, renders figures, nothing else
    README.md        # 1-paragraph purpose + link to thesis_experiment_plan.md section

results/<chapter>/<NN_name>/
    runs/<run_id>/
        config.json          # full, resolved hyperparameter set (no defaults-by-omission)
        metrics.jsonl        # append-only per-step log (one JSON object per line)
        results.json         # final aggregated scalars + downsampled curves (see results_schema.md)
        checkpoints/
            last.pt          # rolling checkpoint; overwritten each save
            best.pt          # best-by-validation-metric; overwritten on improvement
        stdout.log           # mirror of notebook print output (optional but recommended)
    figures/                 # PNG + PDF exports, regenerated by plots.ipynb
```

`<chapter>` is `ch3`, `ch4`, `ch5`. `<NN_name>` matches the experiment number in [../thesis_experiment_plan.md](../thesis_experiment_plan.md) — e.g. `01_cosine_vs_dim`, `04_cosgd_scalability`.

A `<run_id>` is a string of the form `YYYYMMDD_HHMMSS__<short_config_hash>`, e.g. `20260421_163045__a3f1c8`. The config hash is the first 6 hex chars of `sha256(json.dumps(config, sort_keys=True))`. This means rerunning with the exact same config produces a different `run_id` (timestamp changes) but the hash disambiguates config variants within a day.

### Why one folder per experiment?

It keeps the notebook self-documenting — opening `experiments/ch3/04_cosgd_scalability/` shows everything that belongs to that experiment. The thesis cross-reference table in the plan maps directly to folder names.

## 2. Shared code lives in `common/`, not in notebooks

Notebooks should be thin. They declare:

- a `CONFIG` dict (all hyperparameters, dataset choice, seed, trial count),
- a call into `common.training.Trainer` (or the equivalent synthetic-experiment runner),
- writing results to disk.

Anything that appears in a second notebook — a dataset loader, a CNN architecture, a Gram-Schmidt implementation, a checkpoint helper — moves to `common/` *before* the second use. No copy-paste between notebooks.

Suggested module layout:

```
common/
    __init__.py
    optimizers/
        bograd.py           # BOGrad wrapper, parameterised by base optimizer
        cosgd.py            # COSGD
        orth.py             # Gram-Schmidt / Householder / QR implementations
    datasets.py             # returns (train_loader, test_loader, meta) per dataset name
    models.py               # small CNN, ResNet-N, MLP, EmbeddingBag model
    training.py             # Trainer class (see §4)
    storage.py              # run-id, Drive mount, atomic file writes, checkpoint I/O
    plotting.py             # rcParams, palettes, shared curve-aggregation helpers
    seeding.py              # seed-everything helper, paired-trial index generator
```

`common/plotting.py` owns the rcParams block from the IJCNN notebook (fonts, grid, spines). Every `plots.ipynb` imports from it so figures are visually consistent across the thesis.

## 3. Logging

Experiments run under three conditions — local Jupyter, Colab with a live tab, Colab disconnected but still executing. Logging has to be useful in all three.

### 3.1 In-notebook logging (for humans watching)

- Use `tqdm` for per-epoch or per-step progress bars.
- Every `log_every_n_steps` (default 50 for training, 1 for synthetic sweeps), print a one-line summary: `step | train_loss | test_acc | ‖g̃‖/‖g‖ | seconds_elapsed`. Keep it one line — scrolling walls of text are worse than no log.
- At the end of each trial, print a boxed summary: final metrics, total wall-clock time, checkpoint paths, results file path.

### 3.2 On-disk logging (for dead sessions)

Every step that's printed is *also* appended to `results/.../runs/<run_id>/metrics.jsonl` as one JSON object per line. This is the source of truth — if the notebook dies, `metrics.jsonl` has everything up to the last flush.

```python
{"step": 1200, "epoch": 3, "train_loss": 0.82, "test_acc": 0.61, "g_ratio": 0.74, "t": 1714839105.3}
```

`stdout.log` is a best-effort mirror of notebook print output (captured via `contextlib.redirect_stdout` or `common.storage.TeeLogger`). Useful when Colab truncates cell output but the Drive file survives.

### 3.3 What to log

At minimum, every training experiment logs:

- `step`, `epoch`, wall-clock `t` (`time.time()`),
- train loss, test loss, test accuracy (at whatever cadence the experiment dictates),
- `‖g_t‖` and `‖g̃_t‖` if BOGrad or COSGD is in use (cheap, one `.norm()` per tensor per step — do it),
- any experiment-specific diagnostic (e.g. per-class gradient count for COSGD scalability).

Log the quantity even if you don't plan to plot it. Storage is cheap; rerunning a 4-hour CIFAR-100 run because you forgot to log gradient norm is not.

## 4. The `Trainer` contract

`common/training.Trainer` is the one place that knows how to train a model. It accepts a resolved config, handles logging, checkpointing, resume, and returns a `results` object matching [results_schema.md](results_schema.md).

Minimum responsibilities:

- **Seed everything** (`torch`, `numpy`, `random`, `cudnn.deterministic`) from `config["seed"]`.
- **Paired trials**: given `config["seed"]` and `config["trial_index"]`, deterministically produce the per-epoch shuffled index order. All methods compared within the same trial must reuse this ordering. See §7.
- **Step loop**: forward → loss → backward → optimizer step (with BOGrad/COSGD wrapper if configured) → log → maybe-eval → maybe-checkpoint.
- **Evaluation cadence**: `eval_every_n_steps` or `eval_every_epoch`, whichever the experiment specifies.
- **Checkpoint cadence**: §5 below.
- **Early resume**: on construction, check `results/.../runs/<run_id>/checkpoints/last.pt`. If present and config matches, restore state and continue. If absent, start fresh.
- **Results write**: at end of training (or on `KeyboardInterrupt`), write `results.json` via atomic replace (write to `results.json.tmp`, `os.replace`).

Synthetic experiments (3.1, 3.2) won't use `Trainer` — they use a simpler `common.training.run_sweep(fn, grid)` helper that still writes `config.json` + `results.json` per run.

## 5. Checkpointing

Rule of thumb: if a run takes more than ~10 minutes, checkpoint. If it takes more than an hour, checkpoint every 5 minutes or 500 steps (whichever comes first).

A checkpoint file contains:

```python
{
    "step": int,
    "epoch": int,
    "model_state": ...,
    "optimizer_state": ...,
    "bograd_buffer": ...,          # if applicable
    "rng_state": {"torch": ..., "numpy": ..., "python": ...},
    "best_metric": float,
    "config_hash": str,            # must match current config or we refuse to resume
}
```

### Save policy

- `last.pt` — overwritten every `checkpoint_every_n_steps`. Atomic: write to `.tmp`, rename. Otherwise a crash during save corrupts the one checkpoint you have.
- `best.pt` — overwritten when `test_acc` (or configured validation metric) improves. Has the same atomic-rename discipline.

### Resume policy

When `run.ipynb` is re-executed:

1. Compute `config_hash` from the current `CONFIG`.
2. Look for `results/.../runs/<run_id>/checkpoints/last.pt` where `run_id` matches the hash prefix.
3. If found and hash matches: load state, continue from `step + 1`, append to existing `metrics.jsonl`.
4. If found but hash mismatches: raise. The user must either start a new run (new `run_id`) or explicitly delete the old one.

The "match by hash" rule means you can rerun a killed training cell and it will pick up. It also means changing any hyperparameter creates a fresh `run_id` — no silent mixing.

## 6. Saving results

Two things get written at the end of a run:

- `results.json` — the thing plotting reads. See [results_schema.md](results_schema.md) for the exact shape. It contains the full scalar summary, down-sampled curves (don't store every step forever), and a pointer back to `metrics.jsonl` if someone wants the raw log.
- `config.json` — the full resolved config, written *at run start*, not at end. This is so a dead run still has its config preserved for debugging.

All writes use atomic replace. All writes go to the same path in both local and Colab environments; the difference is that Colab's path is a mounted Drive folder.

### Drive mounting (Colab)

`common/storage.py` exposes:

```python
def get_results_root() -> Path:
    """Returns results root. Mounts Drive if running in Colab; returns local ./results otherwise."""
```

It detects Colab via `IS_COLAB = "google.colab" in sys.modules`, mounts `/content/drive` once per kernel, and returns a path under `My Drive/dissertation/results/` (configurable via env var). Every notebook calls this helper — no hard-coded paths.

## 7. Paired trials

For Chapter 5 comparisons (baseline vs COSGD vs BOGrad), the three methods must see the exact same data order within a trial. This is what makes the comparison credible.

Implementation: `common.seeding.paired_shuffle(dataset_size, num_epochs, seed, trial_index)` returns a `(num_epochs, dataset_size)` index array. All three methods in trial `k` call this with the same `(seed, trial_index=k)`.

Trial seeds are derived as `seed = base_seed + trial_index`. `base_seed` is a per-experiment constant set in `CONFIG` (typically `2026`).

## 8. Plotting

`plots.ipynb` is pure presentation. It:

1. Resolves the experiment's `results/` folder (via `common.storage.get_results_root()`).
2. Loads one or more `results.json` files.
3. Uses helpers from `common.plotting` for palette, font sizes, curve aggregation.
4. Renders figures with `fig.savefig(".../figures/<name>.pdf", bbox_inches="tight")` and the same as `.png`.
5. Also renders inline so the notebook itself doubles as a preview.

**Plotting never trains, never reads `metrics.jsonl` directly, never reaches into checkpoints.** If a plot needs something not in `results.json`, the fix is to add that field to the schema and to the Trainer's final write — not to touch training state from the plotting notebook.

Figure naming: `<experiment_number>_<short_description>.pdf` — e.g. `3_1_cosine_vs_dim.pdf`, `4_5_batch_k_heatmap.pdf`. These match the plot IDs in the experiment plan.

### Font and style

Consistent across the thesis. `common.plotting.apply_thesis_rcparams()` sets:

- title 20, label 18, tick 16, legend 18 (tunable via a `density` argument for dense figures),
- grid on, alpha 0.25, top/right spines off,
- figure DPI 120 for inline, export to PDF for vector quality.

## 9. Notebook templates

### `run.ipynb` skeleton

```python
# Cell 1 — setup
%load_ext autoreload
%autoreload 2
import sys; sys.path.insert(0, "../../..")  # or a common helper
from common.storage import get_results_root, new_run_id
from common.training import Trainer

# Cell 2 — config
CONFIG = {
    "experiment": "ch5/01_main_trajectories",
    "dataset": "cifar10",
    "model": "small_cnn",
    "optimizer": "sgd",
    "wrapper": "bograd",        # or "cosgd" or None
    "wrapper_kwargs": {"K": 8},
    "lr": 0.05,
    "batch_size": 128,
    "num_epochs": 30,
    "seed": 2026,
    "trial_index": 0,
    "log_every_n_steps": 50,
    "eval_every_n_steps": 200,
    "checkpoint_every_n_steps": 500,
}

# Cell 3 — run
run_dir = get_results_root() / CONFIG["experiment"] / "runs" / new_run_id(CONFIG)
trainer = Trainer(CONFIG, run_dir)
results = trainer.run()         # handles logging, checkpointing, writing results.json
print(f"Done. Results at {run_dir / 'results.json'}")

# Cell 4 — loop over trials / sweep dimensions (if applicable)
```

### `plots.ipynb` skeleton

```python
import sys; sys.path.insert(0, "../../..")
from common.storage import get_results_root
from common.plotting import apply_thesis_rcparams, load_runs
apply_thesis_rcparams()

exp_dir = get_results_root() / "ch5/01_main_trajectories"
runs = load_runs(exp_dir / "runs")      # returns a DataFrame / dict indexed by config

# Figure 1 — test accuracy trajectories
fig, ax = plt.subplots(...)
# ... render from `runs` ...
fig.savefig(exp_dir / "figures" / "5_1_cifar10_trajectories.pdf", bbox_inches="tight")
fig.savefig(exp_dir / "figures" / "5_1_cifar10_trajectories.png", bbox_inches="tight", dpi=200)
```

## 10. Git hygiene

- `results/` is gitignored. Figures live in `results/.../figures/` and are regenerable — they don't need to be in git.
- `config.json` is small enough to commit if you want to record a specific run's settings; not required.
- The experiment notebooks (`run.ipynb`, `plots.ipynb`) are committed. Clear outputs before committing to keep diffs reviewable (or use `nbstripout` if we set it up).

## 11. When this doc is wrong

Update the doc, then the code. A PR that silently deviates from this document is harder to review than one that edits the document alongside the code.
